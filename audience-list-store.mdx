The audience list store holds the files you upload to an ad platform to build an audience: named account lists, customer match files, contact lists, and suppression lists.

It works the way the [creative drive](/creative-drive) does. The files live in one secure location; this page records where that is and what is in it. The difference is that these files usually contain company or personal data, so what gets written down here is deliberately limited to the metadata.

<Warning>
  **Never paste a list into a document, a brief, or this knowledge base.** No company names, no email addresses, no domains, no row-level data of any kind. A brief links to the list by name; the file itself stays in the store, behind its own access control. Everything on this page is a description of a list, never its contents.
</Warning>

<Note>
  Fill in the link, rules, and rows below with your own. Examples use **Doughnut Labs**, a SaaS company that sells disruptive Doughnut Technology.
</Note>

## Why lists are not customer profiles

These are two different things, and the [customer profile library](/customer-profile-library-overview) is explicit that a profile "describes a type of customer, not a single named person or account."

| | Customer profile | Audience list |
| :-- | :-- | :-- |
| What it is | A description of a type of buyer | A file of specific named accounts or people |
| Where it lives | [Customer profile library](/customer-profile-library-overview) | This store, behind access control |
| Contains data about real people or companies | No | Yes |
| Direction of travel | Profile defines the criteria, list is exported from it | List arrives first, criteria may be someone else's |
| Versioned as | `CP_descriptor_date_version` | See naming below |

Both directions are legitimate. A profile can generate a list, which is what [define a customer profile](/define-a-customer-profile) describes. A list can also arrive from sales, from an event, or from a data provider with no profile behind it, and that list still needs a home, an owner, and an expiry. This store is for the file either way.

<Info>
  A list that arrived without a profile behind it is worth writing a profile for eventually, because a profile is what lets you rebuild the list next quarter. It is not a precondition for launching. Record the selection criteria in the register below and move.
</Info>

## Handling rules

Set these once with whoever owns data protection at your company, then follow them per list.

| Rule | Your decision |
| :-- | :-- |
| Who may upload a list to a platform | _E.g. Media buyer only, after the owner confirms the source is recorded_ |
| Who may download or export a list | _E.g. Nobody. Files are uploaded from the store and not copied out_ |
| Where lists may be sent | _E.g. The ad platform only. Never email, never a shared doc, never a chat message_ |
| Default retention | _E.g. 12 months from the as-of date, then deleted from the store and the platform_ |
| Deletion on request | _E.g. Handled by the data protection owner within the statutory window_ |
| What is recorded in the register | _E.g. Metadata only. Never a row from the list itself_ |

<Warning>
  Deleting a list from this store does not delete it from the ad platform. An uploaded audience persists in the platform until it is removed there too. Whoever owns retention needs both steps on the same schedule, or the deletion is only half done.
</Warning>

<Info>
  The matched count and match rate are the baseline for next quarter's refresh. A list that matched at 72% and now matches at 51% has decayed, and without the first number nobody can tell.
</Info>

## Naming

Every file follows the [file naming conventions](/file-naming-conventions), using the same four-part shape as a customer profile:

`LIST_q2-target-accounts_2026-04-01_v01.csv`

| Part | What it is |
| :-- | :-- |
| `LIST` | Marks an audience file, so it never sorts in with profiles or creative |
| `descriptor` | Lowercase, hyphens, no personal or account names |
| `date` | The **as-of** date: when the list was selected, not when the file was saved |
| `version` | `v` plus two digits |

The as-of date is doing real work here. It is what the [ad set / ad group / variant naming conventions](/ad-set-group-naming-conventions) date identifier refers to, and it is why an audience built in April is comparable to itself and not to the same list refreshed in October.

<Warning>
  A refreshed list is a new version and a new upload, not an edit. Overwriting `v01` with new rows means the audience changed underneath a running campaign with no record that it did.
</Warning>

## Before you upload

<Steps>
  <Step title="Check the row count against the platform floor">
    Every platform has a minimum, and a list below it cannot serve. LinkedIn needs at least 300 rows to upload and at least 300 **matched** companies to run, recommending 1,000. Check the [template](/linkedin-company-list-csv-template) for your platform before promising a launch date.
  </Step>
  <Step title="Record the provenance while the supplier is still in the room">
    Who picked these accounts, on what criteria, as of when. This is the field that becomes unrecoverable fastest, because the person who knows moves on to the next quarter.
  </Step>
  <Step title="Upload and record the match rate before anything else is briefed">
    Matching takes time and can fail the campaign outright. Doing it first means a short list is a scheduling problem, not a write-off of finished creative.
  </Step>
  <Step title="Set the refresh date and the retention date">
    Both, at upload. A list with no refresh date ages silently; a list with no retention date is a data protection problem waiting to be found by somebody else.
  </Step>
</Steps>

## When a list changes mid-flight

Treat the audience the same way you treat attribution and bid strategy: decided at brief stage, left alone after launch.

On account-based campaigns the audience is the campaign. Adding forty accounts in week three changes what the campaign is, and the results from before and after cannot be compared. Nothing in the platform flags this, and the spend line looks continuous.

| If a list has to change | Do this |
| :-- | :-- |
| Accounts were added by the supplier | Upload as a new version, and either start a new campaign or record the change date in the brief so the report can be split at it |
| Accounts have to be removed urgently | Remove them, record the date and the reason. Urgency is a real exception |
| The list is being refreshed on schedule | New version, new upload, recorded in the register, and note the date the audience changed |
