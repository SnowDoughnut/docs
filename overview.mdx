This knowledge base is a set of documents your team fills in once and then reuses. Nothing here describes a specific company. Every workbook ships blank, with grayed `E.g.` examples you delete as you replace them.

Work through the eight stages below in order. Each one feeds the next, so skipping ahead means redoing work. Track your progress on the [setup checklist](/setup-checklist).

<Note>
  You do not need to finish all eight stages before running anything. Stages 1 to 5 are the minimum before your first campaign. The rest can follow.
</Note>

<Info>
  Read [what this framework covers](/what-this-framework-covers) first if you want the scope. This is an operations framework: it fixes the decisions, names, and records that make work reviewable. It does not teach you to operate an ad platform, and several gaps you will notice are deliberate.
</Info>

Two rules make the whole thing hold together:

1. **Fill a workbook once, link to it everywhere else.** A brief that pastes in the positioning statement creates a second copy that drifts. Link instead.
2. **Every finished thing gets saved to its library.** A campaign brief nobody filed is a campaign nobody can learn from.

## The setup path

Each stage uses something from the stage before it. Read the [glossary](/glossary) and the [naming conventions overview](/naming-conventions-overview) first, so every stage means the same thing to everyone.

<Steps>
  <Step title="Stage 1: Locations">
    Fill in the [asset directory](/asset-directory): where creative, video, copy, and landing pages live, who owns each location, and how to get access. Then agree where filled-in workbooks, finished briefs, and reports go.

    | What | Where it lives | Who owns it |
    | :-- | :-- | :-- |
    | Filled-in workbooks | _E.g. Google Drive, /marketing/standards_ | _E.g. Marketing lead_ |
    | Finished briefs | _E.g. Google Drive, /marketing/briefs_ | _E.g. Marketing lead_ |
    | Reports | _E.g. Google Drive, /marketing/reports_ | _E.g. Analytics owner_ |
    | *Add a row* |  |  |

    **Then:** every later stage saves its output to a location recorded here.
  </Step>
  <Step title="Stage 2: Brand">
    Fill in the five brand workbooks in order: [positioning](/positioning), [messaging](/messaging), [brand voice and tone](/brand-voice-and-tone), [visual identity](/visual-identity), [logo usage](/logo-usage).

    Read [brand strategy concepts](/brand-strategy-concepts) and [visual identity concepts](/visual-identity-concepts) first if you want the reasoning.

    **Then:** every creative and copy brief links to these. Nothing downstream restates them. Start at [set up your brand](/set-up-your-brand) for the walkthrough.
  </Step>
  <Step title="Stage 3: Products">
    Fill in the [product catalog](/product-catalog): each thing you sell, with a short form that never changes.

    **Then:** campaign names draw their product values from this list, and every report can group spend by what it was selling. A single-product company can fill this in inside ten minutes and move on.
  </Step>
  <Step title="Stage 4: Customer profiles">
    Fill in a [customer profile brief](/customer-profile-brief) for B2B, or [B2C customer profiles](/b2-c-customer-profiles).

    **Then:** save each finished profile to the [customer profile library](/customer-profile-library-overview). Briefs link to a profile by name instead of redescribing it. See [define a customer profile](/define-a-customer-profile).
  </Step>
  <Step title="Stage 5: Naming and tracking">
    Set the values and patterns every name uses:

    1. Naming values in [campaign](/campaign-naming-conventions), [ad set, ad group and variant](/ad-set-group-naming-conventions), and [ad](/ad-name-conventions) naming conventions. These draw on the products from stage 3.
    2. [File](/file-naming-conventions), [customer profile](/customer-profile-naming-conventions), and [event](/event-naming-conventions) naming conventions. Name each profile from stage 4 with the customer profile convention.
    3. [UTM standards](/utm-standards), after reading [UTM parameters](/utm-parameters). Then build your [event tracking plan](/event-tracking-plan).
    4. The [experiment ID](/experiment-id-convention) pattern, after reading [experiment ID concepts](/experiment-id-concepts).

    **Then:** every campaign uses these names from the first build, every link is tagged from the UTM standard, and every test gets an ID before it launches. See [name something](/name-something) and [set up tracking](/set-up-tracking).
  </Step>
  <Step title="Stage 6: Brand assets">
    Fill in [brand assets](/brand-assets): the source of truth and the asset register. Name the files with the file naming convention from stage 5.

    **Then:** anyone can find the current file and check whether they're allowed to use it.
  </Step>
  <Step title="Stage 7: Reporting">
    Fill in the [marketing reporting data dictionary](/marketing-reporting-data-dictionary), then [KPI definitions](/kpi-definitions), [reporting cadence](/reporting-cadence), and [dashboard standards](/dashboard-standards). Pick a starter pack if one fits: [ecommerce](/ecommerce-metrics-starter-pack) or [sales-led](/sales-led-metrics-starter-pack).

    Read [reporting framework concepts](/reporting-framework-concepts) first for the reasoning.

    **Then:** set up the [flat file](/flat-file-template) that every report reads from. See [report on results](/report-on-results).
  </Step>
  <Step title="Stage 8: Content">
    Fill in [article standards](/article-standards), then set up the [content calendar](/content-calendar).

    **Then:** every article is written and reviewed against the same standards. See [write an article](/write-an-article).
  </Step>
</Steps>
